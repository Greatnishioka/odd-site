# 世界の奇妙なもの図鑑 仕様書

v1.0　2026年11月17日　実装・運用レビュー用

世界各地の珍しい物事を、利用者が見つけて投稿し、他の利用者が探索・議論・補足できる日本語のWebメディア。ニッチな資格や検定も、建築や風習と同じ図鑑に収録する。記事は対象ごとに蓄積し、分類・検索・関連記事・ランダム表示からいつでも発見できるようにする。

## 1　目的と公開範囲

### MVP

公開記事の閲覧と探索、メール認証、記事の投稿と管理者による全件事前審査、4種類のコメント、内部関連記事と出典リンク、訂正提案、第一発見者、基本実績と記事評価、通報と管理画面を提供する。公開記事に広告枠を用意し、広告配信は設定で有効化する。

### 将来スコープ

信頼済みメンバーへの段階的な審査委任、カテゴリ別称号、品質を考慮したランキング、発見ミッション、保存、補足の貢献者表示、関連記事を起点とする発見の連鎖、多言語表示、地図、カテゴリ別の詳細項目を候補とする。

### 掲載方針

対象のジャンルは幅広く受け入れる。審査では説明の明瞭さ、出典で検証できる範囲、重複、安全性を確認する。珍しさや面白さは読者の評価で把握する。伝承や観光企画はその性質を示し、体験・推測・検証可能な事実を区別する。地域文化を見下す表現や、実在人物を晒す投稿は掲載対象外とする。

### 仕様の扱い

管理者の事前審査、コメントの4分類、金銭を伴わない投稿者の実績、将来のコミュニティ審査は基本方針とする。初期分類、件数・時間の閾値、掲載枠、サービス水準は実装・検証用の仮定。公開前に確定する事項は第8章に記載する。

## 2　記事の分類とライフサイクル

### 分類と入力

主カテゴリは必須で1件。初期案は建築・施設、発明・製品、文化・風習、制度・資格、職業、自然、看板・表現、その他。管理者は親子カテゴリを管理でき、初期画面は上位分類を中心に表示する。タグは既存語から0〜5件選択でき、新語は申請する。管理者が表記ゆれを統合し、旧タグURLは統合先へ案内する。

必須項目はタイトル（120字以内）、要約（200字以内）、本文（1万字以内）、主カテゴリ、出典1件以上。出典は資料名とURLまたは書誌情報を登録し、主要な主張との関係を本文に記す。国・地域、別名、画像は任意。画像を添付するときは代替テキストと権利情報を必須とし、位置情報を含むメタデータを除去する。資格記事では認定団体、費用・通貨、取得条件、確認時点を判明範囲で記載する。

### 投稿と審査

下書き → 審査待ち → 公開／差し戻し／却下。投稿者は提出前にプレビューでき、審査待ちの版は固定する。取下げで下書きに戻り、差し戻しは理由を確認して修正・再提出できる。却下時は理由と問い合わせ導線を表示する。管理者は類似記事、出典、画像の権利、センシティブ情報を確認し、版・判断・理由・担当者・日時を記録する。

公開版への変更は、投稿者の改稿または認証済み会員の訂正・追記提案として受け付ける。補足コメントから提案を作成できる。提案には対象版、変更箇所、変更案と根拠を添える。審査中は現行版を表示し、承認時だけ差し替える。対象版が更新済みの場合は再確認してから適用する。重大な問題は管理者が即時非公開にし、再公開は理由を記録して行う。

### 重複と統合

同一対象は原則1記事。審査前にタイトル・別名・出典URLによる候補を出し、管理者が最終判断する。公開済みの重複は正規記事に統合し、公開可能な出典・内部リンクを移し、旧URLを転送する。コメントは文脈と安全性を確認して移す。評価は利用者単位で重複排除し、実績を再計算する。非公開理由により転送が情報露出を招く場合は一般的な非公開表示を返す。

## 3　探索と記事への参加

### 検索とランダム探索

公開中の正規記事のタイトル・別名・要約・本文・タグを検索する。日本語の全半角と英字大小を正規化し、カテゴリ・タグ・国／地域で絞り込む。既定は関連度順、切替は新着順。同順位は公開日時と記事IDで安定化する。該当なしでは条件解除を案内する。ランダム探索は有効な絞り込み内から1件を選び、複数候補がある場合は直前の記事を除く。候補0件では条件解除を案内し、1件では同じ記事を提示できる。

### 関連リンク

記事詳細に出典・外部資料と関連記事を表示する。関連記事は承認済みの内部リンクを優先し、残りを同じタグ・カテゴリの公開記事で補う。会員は関連先と理由を提案でき、管理者が確認して掲載する。コメントでも公開記事へのリンクを記載できる。自己参照・重複リンク・非公開記事を関連記事から除く。非公開の対象は検索・ランダム・API・サイトマップにも露出させない。

### コメント

種類は必須で1つ。雑談は感想や交流、質問は疑問点、補足は追加の事実や出典、体験談は本人の経験を記す。補足の事実主張には出典の提示を促し、記事本文への反映は承認済み提案で行う。記事詳細で種別による絞り込みと時系列表示を提供する。認証済み会員は本文1〜2,000字を投稿し、自分のコメントを編集・削除できる。編集で再判定し、削除・非表示の本文は公開しない。

通常のコメントは即時公開。登録後24時間未満、外部URLが3件以上、スパム判定に該当する場合は暫定的に保留し、本人には状態を表示する。管理者が承認または非公開とし、理由を記録する。記事の非公開中はコメントの閲覧・追加・評価を停止する。投稿頻度の上限に達した場合は再試行可能な時刻を案内する。

### 評価

MVPは記事に「おもしろい」を付ける方式とし、認証済み会員1人につき1記事1件、取消可。自己評価は不可。公開画面に件数を表示する。審査の可否・検索順位・審査権限からは独立させる。停止アカウントによる不正評価を管理者が無効化できる。

## 4　第一発見者と実績

### 第一発見者

記事の公開時に「このサイトでの第一発見者」として投稿者の表示名、プロフィールへの導線、初回提出日を表示する。差し戻し前の提出を含め、同じ対象の承認済み投稿のうち最初の有効な提出時刻を優先し、同時刻は提出IDで決める。下書き、却下、取下げた提出は対象外。審査順の違いで後発が先に公開された場合、先発が承認条件を満たした時点で統合し、管理者が記録を訂正する。

通常の改稿では発見者を維持する。重複・不正は管理者が根拠と変更履歴を残して訂正する。非公開中の記録は公開画面から外し、再公開時に復元する。退会時は表示名とプロフィールの紐付けを外し、公開上は「退会済みユーザー」と表示する。公開記事の編集・審査権限は別途管理する。

### プロフィールと実績

公開プロフィールに公開中の発見記事、実績、公開中の発見件数を表示する。本人には未解除の条件と進捗も表示する。初期の実績案は「はじめての発見」（公開中の第一発見1件）、「分野を越える探検家」（異なる主カテゴリ3種に公開中の第一発見）、「読者に届いた発見」（自身の発見記事1件に有効な評価10件）。

記事公開・統合・非公開・カテゴリ変更・評価更新を契機に再計算し、条件を失ったバッジは表示から外す。実績定義の版と付与・失効日時を記録し、再試行で二重付与しない。発見者の称号はプロフィール上の実績として扱い、運営上の信頼・審査資格は第7章の制度で判定する。報酬の換金や利用者への広告収益分配は設けない。

## 5　権限と画面

### 権限

未ログイン利用者は公開状態の閲覧・検索・ランダム探索ができる。未認証会員はメール認証とアカウント設定を利用できる。認証済み会員は投稿・提案・コメント・評価・通報と、自身の下書き・申請状況・コメントの管理ができる。停止中は公開閲覧のみ。管理者は審査・通報対応・分類・権限管理を行い、審査理由や通報者情報は担当権限を持つ運営者だけが閲覧する。所有者・状態・役割を操作ごとにサーバーで検証する。

## 6　論理データモデル

IDを主キーとする。関連先を参照制約で検証し、日時はUTCで保存する。公開判定は記事状態と公開版を参照する。下表の項目は主要項目。

| エンティティ | 主要項目・制約 |
| --- | --- |
| 会員・役割 | メール一意、表示名、認証・停止・退会状態、役割、権限付与・失効日時 |
| 記事・記事版 | 記事ID、投稿者、状態、公開版ID、初回公開日時、統合先ID。版に本文・要約・別名・地域・分類・出典と画像情報 |
| カテゴリ・タグ | 親カテゴリ、表示名、スラッグ、状態。記事版とタグは中間表で多対多、複合一意 |
| 審査申請・判断 | 対象版、申請種別・状態、提出者・日時、基準版。判断に担当者、理由、日時 |
| コメント・関連リンク | 記事ID、投稿者、本文、種別、状態、編集日時。内部リンクは起点・関連先の組を一意化 |
| 発見者・評価・実績 | 正規記事ごとに発見者1件。評価は記事と会員の組で一意。実績は定義、条件版、会員、付与・失効履歴 |
| 通報・監査ログ | 対象種別とID、理由、優先度、状態、担当、対応結果。監査に操作前後・実行者・日時 |

公開、統合、評価変更は競合時に一意制約と状態照合で整合を維持する。検索更新や実績再計算は変更イベントを再処理できる設計とし、公開判定は検索結果を返す時点でも確認する。

## 7　運用と非機能要件

### 通報と安全性

会員は記事・コメント・参加者を通報できる。理由は誤情報、権利侵害、個人情報、嫌がらせ、危険な誘導、スパム、その他。未ログイン利用者向けに権利侵害等の連絡窓口を設ける。同一会員の同一対象への未解決通報は1件。受付 → 確認中 → 対応済み／措置なしの状態を持つ。個人情報の露出等は優先キューに送る。自動保留はスパムや明確な危険シグナルを条件とし、通報件数だけで公開停止しない。

管理者は注意・修正依頼・非公開・アカウント停止を行い、理由と根拠を記録する。通報者を伏せた状態で対象者に措置理由と異議申立て窓口を案内する。解除時は公開範囲と検索・キャッシュへの反映を確認する。

### コミュニティ審査への移行

段階1は管理者が全件判断。段階2は信頼済み会員の試行審査を導入し、管理者が結果を照合する。委任時は低リスク案件から開始し、新規投稿者の案件は複数の独立した審査者で確認する。段階3では対象領域の承認・訂正・分類をコミュニティが担当し、異議、権利侵害、個人情報、判断が割れた案件は管理者が扱う。

権限は違反履歴、根拠を伴う判断の正確さ、試行審査結果を確認の上で付与する。自己審査・利害関係者による判断を禁止し、操作を監査・取消可能にする。移行時は滞留、判断一致率、覆り率、重大違反の見落としを確認し、問題時は管理者審査へ戻す。資格閾値・必要人数・試行期間は未決。

### 広告と計測

公開記事の本文後に広告枠を設ける。広告表示を明示し、表示領域を事前に確保する。広告の配信不能時も閲覧・コメント・探索を継続できる。ログイン・投稿・管理・非公開ページと配信対象外の記事では表示しない。公開時の配信事業者・同意要件・掲載基準を確認して有効化する。閲覧、関連記事への遷移、ランダム探索、審査時間、広告表示と収益を集計し、計測に本文やメールを送信しない。

### 品質目標

暫定目標は月間稼働率99.5%、公開記事と検索のサーバー応答p95は800ms以内（公開1万件・毎秒20リクエスト）、検索への新規反映は5分以内。日次バックアップ、復旧時点24時間以内・復旧時間8時間以内を目標とし、公開前に復元を検証する。スマートフォンとキーボードで主要操作を完了できること。通信を暗号化し、管理者は多要素認証を必須とする。ユーザー入力は安全に描画し、外部リンクはHTTP／HTTPSに制限する。権限違反、審査滞留、エラー率を監視し、運営へ通知する。

## 8　受け入れ条件と未決事項

### MVP受け入れ条件

| ID | 検証シナリオと期待結果 |
| --- | --- |
| AC01 | 必須項目と出典が揃うと提出できる。下書き・審査待ちの間は他者が直URLや検索から取得できず、承認後は公開される。 |
| AC02 | 差し戻し理由が本人に届き、再提出できる。審査中の改稿は公開版を変えず、承認後に履歴と新しい版が残る。 |
| AC03 | 4種別のコメントを投稿・絞り込みでき、保留条件では管理者承認まで本人と管理者にだけ表示される。 |
| AC04 | カテゴリとタグで絞り込める。ランダム表示は候補0件・1件・複数件で規定どおり。内部リンクは公開中の対象に遷移する。 |
| AC05 | 同一対象の後発記事が先に公開されても、先発が承認された後の統合で発見者が規則どおりになり、旧URL・履歴・実績を確認できる。 |
| AC06 | 自己評価と重複評価を防ぎ、取消・無効化・非公開後に件数と実績が更新される。並行操作や再処理で重複しない。 |
| AC07 | 会員が通報でき、管理者が対象を非公開にすると直URL・検索候補・関連・ランダム・公開APIで内容が取得できない。通報者は公開されない。 |
| AC08 | 未認証会員や停止中の会員は投稿できず、一般会員による他人の下書き閲覧・審査操作は拒否される。 |
| AC09 | 広告を無効化・読み込み失敗にしても、公開記事の閲覧・探索・コメント操作が可能。非公開ページでは広告要求が発生しない。 |
| AC10 | 暫定負荷条件で性能・検索反映目標を満たす。復元試験とモバイル・キーボードでの主要導線を確認する。 |

### 公開前に決める事項

- 運営責任者が掲載基準、初期分類名、出典の例外、画像条件、訂正・異議申立ての手順と対応時間を確定する。

- 運営と実装担当が実績の閾値、コメント保留条件、投稿頻度の上限、通報優先度と公開前の性能試験条件を確定する。

- 運営責任者が配信事業者、広告開始時期、対象地域の同意要件、プライバシー・利用規約、退会後の保存期間と削除手順を確定する。広告開始までは広告を無効にする。

- 審査委任前に、運営責任者が審査員の認定・取消基準、独立判定の人数、移行指標の閾値と管理者審査へ戻す条件を確定する。
